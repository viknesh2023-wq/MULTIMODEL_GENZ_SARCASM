In traditional software engineering rubrics, faculty members frequently include
standard evaluation checkboxes: "Shows Architecture", "Module Walkthrough",
"Shows Database", and "Frontend-to-Backend Reflection".

HOW THIS APPLIES TO OUR SYSTEM:
Our project is a real-time deep learning inference platform rather than a CRUD
(Create, Read, Update, Delete) database application. Sarcasm detection is an
on-demand analytical process. Consequently, our backend DOES NOT store user posts
in an SQL database table like MySQL or SQLite.

Instead, persistent backend storage in this system consists of:
1. Physical Master Datasets: CSV archives with 1,224,831 records (FINAL_DATASETS/).
2. Persistent Feature Stores: 165,385 pre-extracted feature files and partition
   matrices (X_train.npy, X_val.npy, X_test.npy, fusion_metadata.csv).
3. Serialized Model Checkpoints: Pre-trained deep neural network weights (models/)
   totaling over 3.3 GB of safetensors and PyTorch state dicts.
4. Pre-Fitted Preprocessing Objects: Saved StandardScaler (fusion_scaler.joblib).

HOW TO ADDRESS THIS RESPECTFULLY AND ACCURATELY:

academic honesty and show:
- The physical feature store and dataset repository on disk.

  proving that frontend user clicks send HTTP multipart POST payloads to FastAPI,
  which process through the models and immediately reflect on the frontend UI.

SCENE 2: PROPOSED SYSTEM ARCHITECTURE WALKTHROUGH
Estimated Time: 0:45 - 1:30 (45 Seconds)
--------------------------------------------------------------------------------

[SCREEN ACTION: In the left sidebar, click on 'Model Architecture' (or switch
 to the tab displaying GenZ_SarC_Complete_Architecture.png).]

[SAY:]
"Before demonstrating the live application, I would like to briefly present our
proposed system architecture diagram. Please note that this is our complete
system architecture diagram, not an entity-relationship diagram.

Our system operates on a heterogeneous five-branch multimodal pipeline:

First, when a user provides text and an image, the text is processed by our
fine-tuned XLM-RoBERTa transformer to extract a 768-dimensional contextual
representation.

Second, the image is passed through OpenAI CLIP ViT-B/32 to extract a
512-dimensional visual scene embedding.

Third, the image is dynamically tiled and processed through the OpenGVLab
InternVL3-2B foundation vision-language model to extract 1,536 dimensions of
fine-grained visual semantics.

Fourth and fifth, our auxiliary XLM-RoBERTa classifiers extract a 3-dimensional
sentiment probability distribution and a 28-dimensional GoEmotions affective
spectrum.

All five representation streams are concatenated into a single 2,847-dimensional
feature vector. This vector is normalized using our pre-fitted StandardScaler and
passed into our 4-layer Multimodal Fusion MLP, which outputs the final binary
prediction: sarcastic or non-sarcastic.

Finally, an optional Explainable AI reasoner translates the model's signals into
an evidence-grounded natural-language explanation."

[SHOW: Point your cursor across the five branches on the Model Architecture
 page, showing the flow converging into the 2,847-D fusion layer.]

DELIVERABLE 6: QUICK RECOVERY & BACKUP CONTINGENCY GUIDE
================================================================================

If an unexpected issue happens during recording:

1. IF INFERENCE TAKES A FEW SECONDS LONGER THAN EXPECTED:
   Do not panic or restart. Simply continue speaking:
   "The backend is currently dynamically extracting high-resolution visual tiles
   through our 2-billion parameter InternVL vision model..."
   By the time you finish this sentence, the result will have appeared.

2. IF AN UNEXPECTED PREDICTION IS RETURNED (E.g. classified as Non-Sarcastic):
   Do not edit code or restart. State the scientific reality:
   "As we see here, the model outputs a lower confidence score for this sample.
   This illustrates an important research limitation: sarcasm is subjective and
   context-dependent, which is why our system provides confidence scores rather
   than deterministic guarantees."

3. IF OLLAMA IS NOT RUNNING:
   You do not need Ollama! The backend will automatically output:
   "Deterministic Cognitive Reasoner (Local Grounded)" in less than 1 millisecond.
   Simply say:
   "Here, our built-in Deterministic Cognitive Reasoner has generated the explanation
   based on lexical patterns and sentiment distributions."

4. IF THE BROWSER SHOWS "BACKEND OFFLINE":
   Check your backend PowerShell terminal. If Uvicorn crashed or was closed, run
   start_backend.bat and wait 15 seconds for models to finish loading before
   refreshing the browser.

5. GENERAL ADVICE:
   Do one quick, unrecorded practice run from Scene 3 through Scene 5 to warm up
   the PyTorch cache and verify that both servers are communicating smoothly.
